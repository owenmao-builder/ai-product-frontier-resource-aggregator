# AI 新闻关注分 · 直接评分

内容评分 `interest-v2` + 事件集中报道规则 · 2026-09-19

主分数回答“这条消息是否值得你优先阅读”。按现有标题、产品进展和热度直接估分，不等待完整正文、官方引文、竞品对照、A/B 证据或模型 API。分数不是新闻真实性概率或产品质量认证。

## 先看集中报道

同一事件短时间内被多方关注，本身就足以进入重点列表。最近 48 小时内，按不同原始媒体、资讯作者或社区来源计算：

| 独立报道来源 | 事件最低关注分 |
| ---: | ---: |
| 2 | 7.0 |
| 3–4 | 8.0 |
| 5–7 | 8.5 |
| 8–11 | 9.0 |
| 12 及以上 | 9.5 |

最终关注分 = `max(集中报道最低分, 内容关注分)`。即使只有标题、没进入品牌名单、尚无速度/成本/架构数据，多方集中报道仍可独立触发高分。内容本身值得更高分时保留高分，不因平均或重复刷新而被稀释或累加。

媒体、作者/社区分别显示数量和计入的来源。同一来源多篇、同一 URL、相同标题的转载只计一次；纯转发、官方自述和聚合入口不扩大外部报道面。无法区分作者的论坛按社区计一次，不把帖子数当作作者数。超过 48 小时的报道不制造当前热度；所有原文仍可查看。明确出现的新模型名称可先形成事件，不必等待维护者加入产品目录。

例如原内容只有 3.1 分，同一事件有 5 个独立来源集中报道，最终就是 8.5 分；不需要补上性能宣称才能变得重要。

## 再看具体内容

| 维度 | 基础权重 | 目前的判断方式 |
| --- | ---: | --- |
| 模型升级 | 30 | 明确模型发布或版本升级 4/5；新一代或原生多模态等较大变化 4.5/5。旧模型接入、单纯评测不算新模型。 |
| 架构变化 | 30 | 结构大改或 Agent 执行方式重构 4.5/5；框架或运行时更新 3.5/5；接口与插件更新 2/5。 |
| 速度提升 | 25 | 按来源宣称的加速倍数：>1 倍为 2/5、≥2 倍为 3/5、≥5 倍为 4/5、≥10 倍为 4.5/5、≥20 倍为 5/5。区间按较小倍数。 |
| 成本下降 | 25 | 按成本变为原来的 1/N 判断，N 使用与速度相同的档位；下降 50% 等于 2 倍降本，不是 50 倍。 |
| 产品热度 | 25 | 使用新鲜的 GitHub 周增星、HN 近 7 天讨论，取较强信号；没有可用数据时按 2.5/5 中性估值并明确标注。 |
| 关注匹配 | 15 | 命中关注产品且有技术/产品事件为 5/5；未入名单、但有模型升级/架构变化/效率变化为 3/5；普通品牌提及为 0。 |

只计算适用维度：模型发布不必同时改变架构；纯框架新闻不必发布模型。两项都不适用时使用权重 30 的“产品/技术进展”：普通产品发布/功能更新 4，旧能力集成 2.5；研究、分析、安全、政策信息默认 2.5；其他消息默认 1.5。传闻、融资、账号交易等非正式产品技术事件默认为 1，且不取得产品热度或关注匹配加分。

内容关注分 = `2 × Σ(维度分 × 权重) / Σ(适用权重)`，范围 0–10，保留一位小数。这里的权重是归一化前的相对权重，不要求每条新闻满足所有维度；再与集中报道最低分取较高值。

例如模型升级 4、热度未知 2.5、关注匹配 5，架构不适用：`2 × (4×30 + 2.5×25 + 5×15) / 70 = 7.4`。架构大改 4.5、相同热度与匹配条件，则为 7.8。即使证据状态为 C，两条仍显示关注分。

速度和成本只在新闻提供相关变化时参与，不要求每条新闻都有这些数据。标题、已读取正文和最近 7 天的对应官方发布说明都可提供信号；未读到数据先估分，补齐后更新。官方补充说明标出来源与适用场景，不当作其他媒体的独立观点。复刻、衍生、接入和教程不会继承原模型发布的收益。否定句、无关数字及推荐文章区不作为提升依据。

Jev 的[官方发布说明](https://typesafe.ai/blog/introducing-system-one-models-and-jev)介绍新架构、并行采样和 RLCD，并宣称其 System One 工作流测试速度快 193.6 倍、成本约为对照的 1/444.6。模型 4.5、架构 4.5、速度 5、成本 5、热度 5、技术兴趣 3，得到 `2 × (4.5×30 + 4.5×30 + 5×25 + 5×25 + 5×25 + 3×15) / 150 = 9.2`。热度未知时为 8.4。标签为模型进展、推理加速、成本下降、架构创新；这些数据不代表所有任务同等收益，也不需要独立验证后才取得关注分。

已观测热度沿用阈值：GitHub 周增星 ≥500，或近 7 天 HN ≥100 赞。分量从 10 起按翻倍加 5、最高 25，再除以 5 转为维度分；不是把星数或赞数冒充验证结果。超过 24 小时的采集热度失效，回到明确标注的中性估值。

新闻按关注分降序排列，同分再看事件优先级和来源发布时间。只是出现 Harness、可插拔、黑箱可见等词不会自动获得高分；这些是对应新闻的关注点，不是通用要求。

## 证据与中文重点

- A 充分：已有直接材料支持关键判断。
- B 待验：有原文，但关键收益或比较结论尚未核实。
- C 不足：只有标题或有限材料。仍可显示关注分，不把它当成低分。

主徽标显示“关注分”；证据状态、分项值、实际权重及热度缺口在展开的评分依据中显示。7 分及以上提供可展开的内容。只有标题时标为“标题要点”，不冒充全文分析；已有完整中文摘要继续使用。未翻译的高分公开标题沿用原项目 Google 翻译服务，每轮最多处理今天 5 条，失败不阻断分数。

可选的模型 API 仅用于补充正文分析和更完整的中文重点。未配置 API 也能立即评分。历史的原文核验评估仍保留，其旧规则见 [旧版重要性标准](SCORE_POLICY_V2.md)；旧版证据门槛不再限制当前关注分。

## 更新范围

每次刷新按最新热度和关注名单更新今天的关注分，保存到本机独立缓存；旧评分材料和阅读记录保留。过去日期不重新评分，继续读取已保存的分数，包括 `interest-v1`。规则改动默认只检查当天的一小组样例。

## 同一事件与媒体关注

同一具体产品/版本与同一动作、72 小时内的报道合并展示；不同版本、故障、传闻、教程、接入其他产品或后续定价变化分开。只有品牌相同不会合并，无法可靠判断时保留独立条目。按原始媒体域名或作者身份计数，聚合入口指向 AIbase 等原文时归回该媒体；同一家多篇只计一次。资讯作者和社区属于外部关注来源，单独标注，不冒充媒体机构。

事件内容分取最高文章关注分，再与集中报道最低分取较高值。替代过去最多 +1.0 的附加分机制；集中报道独立确定最低关注级别。只更新今天的事件展示，不回写历史文章评分，刷新不会累加。热度不改变证据等级。

菜单栏与内置看板按事件展示和筛选，来源搜索覆盖事件内所有文章。展开阅读后按事件记录已读，新增转载保持已读。展开内容含核心分析、各家关注点、标题/正文依据与原文链接。每轮最多为今天 3 个事件读取 9 篇公开正文，其中保留一个名额给不足 7 分的模型/架构/效率消息，避免标题简略导致一直低分。最多翻译 6 段尚无中文的公开材料；已有内容先显示，读取失败保留标题归纳，无需模型 API。正文摘录只选含事件主题和分析维度的完整句子，跨媒体归纳不声称报道中的数字已获验证。
